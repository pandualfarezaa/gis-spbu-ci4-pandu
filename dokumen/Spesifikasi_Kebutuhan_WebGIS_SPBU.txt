  Dokumen Spesifikasi Kebutuhan Sistem






1. Pendahuluan


1.1 Latar Belakang

Data lokasi Stasiun Pengisian Bahan Bakar Umum (SPBU) perlu disajikan secara informatif agar mudah dicari, dipantau, dan dikelola. Informasi dalam bentuk tabel saja kurang membantu pengguna memahami persebaran lokasi. Oleh karena itu, dikembangkan WebGIS SPBU yang menampilkan lokasi SPBU pada peta interaktif serta menyediakan pengelolaan data melalui halaman admin.



1.2 Tujuan

  • Menyediakan peta interaktif persebaran SPBU di wilayah Brebes dan Banyumas.

  • Memudahkan pengguna melihat detail, alamat, foto, status, dan koordinat SPBU.

  • Menyediakan halaman admin untuk mengelola data SPBU, wilayah, jenis SPBU, dan pengguna.

  • Menyediakan REST API sebagai pengembangan dan integrasi dengan aplikasi lain.



1.3 Ruang Lingkup
Sistem mencakup halaman publik WebGIS, autentikasi pengguna, registrasi akun, dashboard admin, pengelolaan data SPBU, pengelolaan wilayah, pengelolaan pengguna, pengaturan pusat peta, serta REST API data SPBU dan referensi.



2. Gambaran Umum Sistem
2.1 Aktor Sistem

  Aktor	Deskripsi	Hak Akses	

  Pengunjung	Pengguna umum yang mengakses halaman WebGIS.	Melihat peta, memfilter wilayah/jenis, dan melihat detail SPBU.	

  Pengguna Terdaftar/Admin	Pengguna yang sudah login ke sistem.	Mengakses dashboard dan fitur administrasi.	

  Pengelola Sistem	Pihak yang bertanggung jawab terhadap data dan konfigurasi sistem.	Mengelola seluruh data master dan pengaturan peta.	



2.2 Arsitektur Teknologi

  • Frontend: HTML, CSS, JavaScript, Bootstrap/AdminLTE, dan Leaflet.js.

  • Backend: PHP dengan framework CodeIgniter 4.

  • Database: PostgreSQL.

  • API: REST API berbasis JSON untuk data SPBU dan data referensi.

  • Web server: PHP development server atau web server yang diarahkan ke folder public.

5. Use Case Utama

  • Pengunjung membuka halaman utama dan melihat peta SPBU.

  • Pengunjung memilih wilayah atau jenis SPBU untuk memfilter marker.

  • Pengunjung membuka popup marker dan memilih detail SPBU.

  • Pengunjung melakukan registrasi akun melalui halaman registrasi.

  • Pengguna melakukan login untuk masuk ke dashboard.

  • Admin menambah, mengubah, atau menghapus data SPBU.

  • Admin mengelola wilayah dan GeoJSON yang ditampilkan pada peta.

  • Aplikasi eksternal mengambil data melalui endpoint REST API.



6. Data dan Database

  Tabel	Fungsi	Contoh Data	

  tbl_spbu	Menyimpan data lokasi SPBU.	Nama, jenis, alamat, foto, status, lokasi, wilayah.	

  tbl_wilayah	Menyimpan batas wilayah peta.	Nama wilayah, GeoJSON, warna.	

  tbl_jenis	Menyimpan jenis SPBU dan marker.	Jenis, file marker.	

  tbl_user	Menyimpan akun pengguna.	Nama, email, password, foto pengguna.	

  tbl_setting	Menyimpan konfigurasi pusat peta.	Nama aplikasi, koordinat, zoom.	

  tbl_provinsi, tbl_kabupaten, tbl_kecamatan	Menyimpan data referensi wilayah administratif.	Nama dan relasi wilayah administratif.	



7. REST API

  Method	Endpoint	Fungsi	

  GET	/api/spbu	Menampilkan daftar SPBU dan filter.	

  GET	/api/spbu/{id}	Menampilkan detail satu SPBU.	

  GET	/api/spbu/geojson	Menampilkan data SPBU dalam format GeoJSON.	

  POST	/api/spbu	Menambahkan data SPBU.	

  PUT	/api/spbu/{id}	Mengubah data SPBU.	

  DELETE	/api/spbu/{id}	Menghapus data SPBU.	

  GET	/api/jenis, /api/provinsi, /api/kabupaten, /api/kecamatan, /api/wilayah	Menampilkan data referensi.

9. Validasi dan Keamanan

  • Form penting menggunakan aturan wajib isi, format email, panjang password, dan format file.

  • Halaman admin dilindungi oleh filter autentikasi session.

  • Route menggunakan daftar eksplisit dan auto-route dinonaktifkan.

  • Data koordinat divalidasi sebelum digunakan pada peta/API.

  • Konfigurasi password database tidak boleh dipublikasikan di repository.


Catatan keamanan: sebelum repository dibuat publik, gunakan password database yang aman dan jangan commit file `.env`.

10. Instalasi dan Menjalankan Sistem

  • Clone repository dari GitHub.

  • Jalankan composer install.

  • Siapkan PostgreSQL dan database db_gis_spbu_ci4.

  • Salin file environment menjadi .env dan isi konfigurasi PostgreSQL.

  • Pastikan ekstensi PHP intl, mbstring, dan pgsql aktif.

  • Arahkan web server ke folder public.

  • Atau jalankan php spark serve.

  • Buka halaman utama, kemudian uji login, registrasi, CRUD, peta, dan API.
